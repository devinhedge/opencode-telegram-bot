# Makefile Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A root `Makefile` for macOS and Linux with the `help` and `install` targets.

**Architecture:** One `Makefile`. Targets are plain recipes; the root refusal is a `$(error ...)` that expands before the first npm command, so tests can exercise it with `make -n`. Tests run `make` only as a dry run, as the print-only `help`, or against a fake `npm` in a temp directory.

**Tech Stack:** GNU Make 3.81 or later (the macOS default), npm, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-14-makefile-design.md`

## Starting point

Commit `f98f807` already holds a first `Makefile`, `tests/makefile.test.ts`, and the README section. Each task below lists what that commit already satisfies and the delta still to build. The delta is where the plan finds two defects in the first pass: the root refusal fails open when the user id cannot be read, and no test shows that a failing step stops the recipe.

## Global Constraints

- macOS and Linux only; no Windows support, and the test file is skipped on Windows.
- Targets run as the invoking user; `install` refuses root, `help` runs as root.
- The refusal happens before any other recipe command.
- No target needs `sudo`; `help` and `install` use none.
- `install` runs exactly `npm ci`, `npm run build`, `npm link`, in that order, from the repository root, and never runs `opencode-telegram config`.
- `help` is the default target and changes nothing.
- A failing step stops the target.
- Tests never run `npm ci`, `npm run build`, or `npm link` for real, and any test that starts a real process opts in through `allowRealProcesses(reason)`.
- Current-design wording in docs; no counts of targets; no emojis.

## Review Focus

- The user id cannot be read (`id -u` fails or prints nothing): `install` must refuse, not proceed as if non-root. Pinned in Task 2.
- A step fails (for example `npm run build`): `npm link` must not run and make must exit non-zero. Pinned in Task 2.
- `make` is started from another directory (`make -C <repo>`): `help` and `install` behave the same. Pinned in Tasks 1 and 2.
- An unknown target: make exits non-zero and nothing runs. Pinned in Task 1.
- An existing global install of the package conflicts with `npm link`: not testable without touching the machine; it is the manual check in "Open items".

### Task 1: The help target

**Files:**
- Create: `Makefile`
- Test: `tests/makefile.test.ts`

**Interfaces:**
- Consumes: nothing.
- Produces: `.DEFAULT_GOAL := help`; the variable `CURRENT_UID` (overridable on the command line, used by Task 2); the `.PHONY` list.

Already in `f98f807`: the default target, the usage line plus one `name  description` line per target, and tests for the default target, the explicit `help` target, and `help` as root.

- [ ] **Step 1: Write the failing tests** in `tests/makefile.test.ts` (extend the existing helper `runMake(args, env?)`, which spawns `make` with `cwd` the repo root, a `PATH`-only environment, and a 10 s timeout; the file opts in with `allowRealProcesses`):
  - `"is the default target and lists install and help"`: `runMake([])` exits 0 and the output has lines matching `/^\s*install\s+\S/m` and `/^\s*help\s+\S/m`.
  - `"prints the same text for an explicit help target"`: `runMake(["help"]).output` equals `runMake([]).output`.
  - `"still works as root"`: `runMake(["help", "CURRENT_UID=0"])` exits 0.
  - `"behaves the same from another directory"`: `runMake(["-C", PROJECT_ROOT, "help"])` run with `cwd` set to `os.tmpdir()` exits 0 and prints the same text as `runMake([])`.
  - `"fails on an unknown target without running anything"`: `runMake(["nope"])` exits non-zero and the output matches `/No rule to make target/`.

- [ ] **Step 2: Run** `npx vitest run tests/makefile.test.ts`. Expected on the current tree (`f98f807`): all five PASS, because the first pass already satisfies them; the two new tests are regression pins. On a tree without the `Makefile`, all five are RED.

- [ ] **Step 3: Implement** `help` in `Makefile`: `@printf` the usage line, then one line per existing target with the name padded to 10 characters. `runMake` gains a `cwd` option for the new test.

- [ ] **Step 4: Run** the same command. Expected: all `help` tests PASS.

- [ ] **Step 5: Commit** `feat(make): add the help target`.

### Task 2: The install target and the README

**Files:**
- Modify: `Makefile`, `tests/makefile.test.ts`, `README.md` (section "Make Targets (macOS and Linux)")

**Interfaces:**
- Consumes: `CURRENT_UID` and `.PHONY` from Task 1.
- Produces: `install`; the refusal messages `make install must not run as root; run it as the user who will use the bot` and `make install cannot determine the user id`.

Already in `f98f807`: the root refusal for uid `0`, the three npm steps in order, a no-config-wizard test, a root-refusal test, and the README section.

- [ ] **Step 1: Write the failing tests** in `tests/makefile.test.ts`:
  - Dry-run (`make -n install CURRENT_UID=1000`) cases, already present: `"installs dependencies, builds, and links the CLI, in that order"` and `"never runs the config wizard"`.
  - `"refuses to run as root before any npm command"` (`CURRENT_UID=0`), already present: exits non-zero, output matches `/must not run as root/`, and contains no `npm `.
  - `"refuses when the user id cannot be determined"`: for each of `CURRENT_UID=` (empty) and `CURRENT_UID=abc`, `make -n install` exits non-zero, matches `/cannot determine the user id/`, and contains no `npm `.
  - `"behaves the same from another directory"`: `make -C <repo> -n install CURRENT_UID=1000` run with `cwd` set to `os.tmpdir()` prints the three npm steps in order.
  - `"stops at the first failing step and never links"`: create a temp directory holding an executable `npm` shell script that appends its arguments to `calls.log` and exits 1 when its first argument is `run`; run `make install CURRENT_UID=1000` with `PATH` set to that directory followed by the original `PATH`. Assert a non-zero exit and that `calls.log` is exactly `ci` and `run build`, with no `link` line. Remove the temp directory in `afterEach`.

- [ ] **Step 2: Run** `npx vitest run tests/makefile.test.ts`. Expected on the current tree (`f98f807`): the unreadable-id test is RED for both values (the first pass prints the three npm steps for an empty or non-numeric id; checked with `make -n install CURRENT_UID=`). The failing-step test and the other-directory test are expected to PASS, as regression pins.

- [ ] **Step 3: Implement** `install` in `Makefile`: the first recipe line is `$(error ...)` unless `CURRENT_UID` is a positive integer, with the root message for `0` and the unreadable-id message otherwise; then `npm ci`, `npm run build`, `npm link`. `CURRENT_UID` is read with `$(shell id -u 2>/dev/null)`. The check is plain make functions (no shell-specific syntax beyond POSIX `sh`) so it works on Make 3.81.

- [ ] **Step 4: Update the README** section so it states: `make install` refuses root and also refuses when the user id cannot be read; it runs the three commands; it does not run setup. Current-design wording.

- [ ] **Step 5: Run** `npx vitest run tests/makefile.test.ts`, then `npm run lint`, `npm run typecheck`, and the full `npm test -- --testTimeout=60000`. Expected: all pass.

- [ ] **Step 6: Commit** `feat(make): add the install target`.
